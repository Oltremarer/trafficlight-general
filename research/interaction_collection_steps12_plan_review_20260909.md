# 第一步与第二步：实施计划、参数审查及修订配置

日期：2026-09-09。范围：“逐秒记录器/标签”和“同根反事实采集”。根据用户最新指示，移除额外的一致性检查并开始实现、执行；保留普通代码测试、文件完整性和断点续采处理，不启动模型训练。原文的参数审查是设计依据，不代表采集结果。

本稿是对 `interaction_world_model_redesign_20260909.md` 中步骤 A/B 的实施细化。第一、二步的参数以本稿为准。模型结构、训练超参数、控制器比较、LLM、incident 和大网迁移均不在本轮执行范围。

## 1. 这两步最终要交付什么

从某一时刻的杭州路网保存现场，分别执行“不改”“只改 A”“只改 B”“同时改 A/B”，得到同样180秒内每条车道的排队分布、累计等待、过路计数和接纳状态。

第一步交付：**能正确记录，也能回到完全相同现场的采集程序。**

第二步交付：**可追溯的基准、单项、双项及联合后果数据。** 它们可以用来检验交互、以后训练 World Model；采集结束本身不等于交互稀疏或模型有效。

实施顺序：固定指标/时序 → 实现记录与恢复 → 按固定清单建根 → 采集分支并保存索引。不执行A→B→A重复一致性检查，不设逐秒守恒门槛，不另加性能pilot或参数搜索。

## 4. 第一步：记录器与标签的实施计划

### 4.1 先固定物理量，避免重复记录含义相同的目标

每个tick读取一次批量车辆速度/距离与车道ID列表，再计算新schema；尽量复用同一份观测，不因多个模块重复请求所有车辆。只有不在普通lane映射里的running车辆才需要补查drivable，已知映射缓存。车辆在laneLink内也要计数。

| 保存量 | 定义与类型建议 | 可以导出什么 |
|---|---|---|
| 每车道三段N/Q | 车辆数/停车数，uint16；入库前检查范围，禁止溢出后截断 | 全车道N/Q、空间积压、逐窗等待 |
| 三段速度总和 | float32；采集时先以float64汇总 | 平均速度；N=0处用掩码，不当作堵死 |
| 入口尾车距离/速度 | 各float32；基于原始double判断接纳，再压缩 | 接纳连续状态；空车道由N=0识别并屏蔽尾车字段 |
| 速度损失和 | 每车道每秒sum(max(0,1-v/v_ref))，float32；汇总用float64 | 5 s/180 s速度损失；首版v_ref=min(车辆maxSpeed,车道maxSpeed) |
| lane进入/离开计数 | 每秒事件数，uint16 | lane级存量守恒及局部流量 |
| movement放行/接收计数 | 分别统计lane→laneLink和laneLink→下游lane，uint16 | 释放波与下游到达；不假定同秒发生 |
| laneLink内部N/Q/速度损失 | 按所属路口汇总，N/Q用uint16、损失float32 | 补足路口内车辆和等待，检查路口存量守恒 |
| 边界B/生成/入网计数 | 按16个入口道路记数；uint16按范围检查 | B及入口外等待，防止隐藏需求积压 |
| 接纳不可用状态 | 每lane每秒uint8；对5 m新车复现固定源码的canEnter条件 | 每5 s接纳不可用秒数；不是已证实的阻塞原因 |
| 实际信号 | 每tick使用的engine phase、阶段与阶段计时 | 可核对的5 s过渡、25/30 s绿灯与公共续策 |

laneLink的速度损失参考首版取当前车辆与所连道路速度上限的最小值；转弯自身也可能产生损失，因此称“速度损失代理”，不称精确的信号额外旅行延误。动作差值仍由配对分支计算。原始数据说明中写清这一口径。

容量只作为派生尺度：对应车道/区段长度除以5+2.5 m，明确是储车量估计，不是引擎硬容量；不按这个估计clip车辆数。pressure、占用比例、停车比例后处理计算，不再独立采一组可能冲突的标签。

### 4.2 将时间边界说清楚

对整数τ=0…179：

1. 在t+τ先应用应发生的信号请求/阶段切换。
2. 记录这1 s实际使用的信号。
3. 执行一次next_step，到t+τ+1。
4. 读取物理状态；比较前后车辆位置以记录该1 s的crossing。
5. 将步后停车数、速度损失和边界等待加入该1 s累计。

例如首个5 s窗口的等待，是Q(t+1)+…+Q(t+5)乘1 s。后续窗口不重复计边界样本。状态采样和“刚过去1 s使用的相位”分别存，不能把t+5的交通状态与t+5即将生效的新相位混称为同一段执行日志。

这定义的是1 s离散积分，不声称连续时间精确积分。主要目的是所有分支和训练标签使用同一可复算口径。

当前`environment.py`在step末才更新current_phase/phase_elapsed_s；实现采用独立`SignalRunner`记录实际相位及区间时钟，不改旧环境、不读取其尚未更新的周期末字段。公共动作语义不改变。

### 4.3 车辆跨边界与入口等待

维护每辆当前车辆的上次lane/drivable、归属入口与必要路由进度。先区分普通lane、laneLink和未入网buffer三类，再统计：

- lane→laneLink：进口放行。
- laneLink→lane：下游进入。
- 一秒内从lane直接观测到下一条lane：由合法road连接恢复该tick跨越；不能据此编造精确亚秒通过时刻。
- 新running车辆：区分从buffer入网与本tick直接生成入网。
- 消失车辆：有终点/路线证据才计出网；异常删除/无效路线另计，不装作正常throughput。

未入网车辆的get_vehicle_info只有running标志，不能靠它读road。固定源码使用flow_i和车辆计数构造身份，故可由已核验的生成身份映射到flow首条道路。映射属于离线记录器，不把车辆未来完整路线提供给World Model。无法识别的身份必须标记，不默默丢弃。

根据用户要求，不执行逐秒守恒检查，不以计数闭合作为采集门槛。无法归属的跨越、异常消失等保存为`unresolved_events`，不冒充正常throughput；不受支持的车辆身份或drivable显式报错。

### 4.4 保存/恢复真正的根状态

本次实现的接口：

- Backend：保留原`snapshot()`读观测，新增`capture_archive()`/`restore_archive()`及文件加载，包装Engine存档。
- 独立SignalRunner/Recorder：保存当前相位、计时、150 s历史和上次车辆位置/身份缓存；根均位于30 s动作结束的绿灯阶段，无额外中途阶段状态。
- Collector：根的历史信息与分支局部累计分开；每次恢复后将本分支W/D/事件计数清零，不能携带上一分支或根以前的累计。

一个进程独占一个Engine，五个根的内存Archive只在其所属Engine上恢复，不将有内部对象引用的Archive跨进程共享。正式运行遇到两个截断的Archive JSON文件，故采集器不再使用Archive文件dump/load；进程重启时根据原flow/seed/动作序列重建五个根，再跳过已提交分片。分支不改变flow、seed或车辆动力学参数。这是实际文件加载故障后的实现修正，不是新增一致性实验。

原MetricCollector中的整小时逐车累计不是本实验的监督目标，分支模式避免重复维护和复制这套无关累积器；原运行模式保持不变。历史rich观测仍可按原口径用于重放核对，新物理观测独立保存。

固定seed和恢复随机状态保证可重复实验条件，但不能自动承诺不同动作下每个随机事件都消费完全相同的随机数。此阶段报告固定版本/固定需求/固定根条件下的模拟器干预效果，不宣称已经证明配对降方差。

### 4.5 按用户指示移除一致性检查

不运行真实Engine的A→B→A重复，不运行逐秒守恒检查，也不将其设置为正式采集前置门槛。普通代码测试覆盖动作分支计数、阈值及积分口径和信号时序；它们不是新增CityFlow实验。

保留正常报错、无符号计数溢出保护、原子写盘、文件hash和已提交分片的断点恢复。交互很小、动作效果差或非零未归属事件本身不触发样本筛除。

第一步以记录器实现和正式数据能够保存、读取为交付依据；不再把同根重复一致性作为完成条件，也不声称已经通过这一被移除的检查。

## 5. 第二步：固定清单采集同根分支

### 5.1 选36个flow，保持已有数据边界

使用远端杭州既有数据计划和索引：

`/mnt/pan/world-model/runs/20260815T134500Z_6edfc46_formal_2000_per_city_v1/hangzhou`

本次重新读取确认：110 train、13 validation、13 test；三个来源base_00/base_01/base_02，train有4种profile，validation/test各2种profile，所需分层单元均有候选。FixedTime与MaxPressure都覆盖136个flow。

- train：3来源×4 profile，每格取2个，共24。优先选不同demand_scale的两条；从满足这一约束的候选对中按固定子seed均匀选择。
- validation：3来源×2 profile，每格取1个，共6。
- test：3来源×2 profile，每格取1个，共6。

先按稳定flow_id排序，再按固定随机种子选择；保存完整selected_flows清单、来源、profile、倍率、计划车辆数、hash及选择规则。源文件不复制改写，不新增需求扰动。不同文件共享源数据的事实保留；test是原先定义的stress分布，不重新称为IID测试。

24/6/6是当前采集预算，不是统计功效证明；特别是6个test flow不足以支撑广泛的跨需求稳健性结论。此处先形成机制数据，不把后续正式算法评价的样本充分性视作已经解决。

所选每个flow对两策略均取episode 0，并读取对应manifest中的原模拟器seed与动作序列。两种根策略的seed本来可以不同；它们不是用来估计策略的因果差异。同一个根的所有动作分支才必须共享同一个seed/Archive。

只校验本次选中manifest、flow、roadnet和动作轨迹的存在性/hash/schema，不重扫全部2000条数据。不从原30 s轨迹“插值”伪造逐秒标签。

### 5.2 建360个根，从中固定72个完整根

每个flow/策略从零初始化，用已保存动作重放至3000 s，途中在五个指定时刻保留内存Archive，落盘150 s历史和根元数据。重放期间不重新调用策略选动作；这样旧观测的容量问题不会因本次修正而偷偷改变历史动作。

每根记录积压分数S=全网停车数（含laneLink）+边界未入网数，单位辆；同时另存活动车辆数、接纳不可用车道数和真实相位。S仅用于选择完整参照根，不作奖励，也不叫拥堵真值标签。

每个flow必须选一个FixedTime根和一个MaxPressure根作为完整根：

- 按flow固定排序的奇偶轮换：一类flow取FixedTime的S中位根和MaxPressure的S最大根；另一类交换角色。
- 中位取该策略五个S值的第3个有序值；并列取最早时刻。
- 选择只用干预前观测，算法在读取test根之前固定；不使用任何分支未来效果。

得到72个完整根，其余288个做部分pair采集。所有360根都保留，不因空状态、弱交互或重拥堵被丢弃。完整根是刻意选出的代表状态，不是全体时刻的无偏随机样本；结果需注明采样范围。

实际按flow/策略任务工作，每个进程只保留当前任务的五个内存Archive，选择完整根并处理分支后释放。选择角色由flow奇偶预先确定，不需要同时保留两策略Engine；不同任务并行。

### 5.3 所有分支共用的信号安排

根时刻记t；a0是各路口当时的当前相位，next按本路口合法相位表循环。

| 相对区间 | 请求 |
|---|---|
| 0–30 s | 本分支候选联合动作；参考分支为a0 |
| 30–60 s | next(a0) |
| 60–90 s | next²(a0) |
| 90–120 s | next³(a0) |
| 120–150 s | a0 |
| 150–180 s | next(a0) |

后五条请求在所有分支中相同，由根预先生成；保留环境原切换规则。**相同请求不等于30 s后立即有相同灯态**：例如某候选已经处于next(a0)，它在30 s无需切换，而参考分支需要5 s过渡。

因此本实验精确定义为“只改变第一条30 s信号请求，在公共后续请求表下的总后果”，包含返回公共表的切换差异；不能说实际灯态严格只在前30 s不同。首版不增加人为强制全红来消掉这一差异。

### 5.4 每个根做哪些分支

**完整根：每根1193条。**

- 基准：1。
- 单项：16×3=48。
- 双项：全部120对×3×3=1080。
- 多路口联合：3/4/8/16个路口同时改变，各16组，共64。

3/4/8路口联合各8组从拓扑上连通的路口集合采样，另8组从全网等概率采样，并记录实际空间跨度；后一组叫“全网随机”，不保证恰好分散。16路口组只改变非参考相位组合。所有候选按完整动作向量去重并补足对应数量，规则仅依赖静态图、a0及固定seed。

**部分pair根：每根337条。**

- 基准1+全部单项48。
- 从120对中均匀无放回采32对，每对全做9个动作，合计288。
- 不再做无法齐全重构的64个多路口联合分支。未采pair设为missing，不设为0。

这些部分pair根仍可用来学习不同状态下的单/双效应；一条双项标签需要的基准和两个单项均已存在。

**四路口精确表：每完整根最多新增189条。**

按flow固定奇偶在两个面板间轮换，两策略使用同一个面板以便解释：

- 角落面板：intersection_1_1、intersection_1_2、intersection_2_1、intersection_2_2。
- 中央面板：intersection_2_2、intersection_2_3、intersection_3_2、intersection_3_3。

其余12路口第一条请求固定a0；仍使用同一公共续策。面板4^4=256条，其中1个基准+12个单项+54个双项已采，所以最多补189条。若64个联合方案中已有对应动作，再去重。面板只能支持该四路口条件最优/精确展开，不能称全网最优。

### 5.5 成组索引、标签与训练权限

branch_id由root_id、完整6×16请求表和protocol版本的稳定哈希生成；未改变的外部配置由root_id包含。基准和单项只存一次，四分支标签用ID引用。相减先将uint16提升到int64；浮点量先提升到float64，再计算e_i及e_ij。保存原始后果，不另复制数倍体积的所有差值数组。

某根的所有数据保留同一个flow split；禁止按分支随机拆训练/验证/测试。同一flow的根和分支相关，不能把196,560条分支说成196,560个独立交通样本。

给多路口联合及面板内3/4路口改动标记`compositional_holdout=true`。单/双标签训练时不能读取这些未来目标；即使它们属于train flow，也只可用于另行声明的结构诊断。test后果本轮采集后仅做数据完整性检查，不用来调100 m区段、完整根规则或候选生成规则。

第二步完成条件：全部计划中的唯一分支有完整记录与索引，必要对照引用齐全，180个tick/36个窗口对齐，所选flow hash和split一致，失败/缺失明确为缺失而非成功。高阶残差和模型训练不属于本轮完成条件。

### 6.2 存储方案

使用新目录与schema，不覆盖旧NPZ/checkpoint：

```text
/mnt/pan/world_model_interaction/<run_id>/
  protocol.json                 参数、指标定义、源码/二进制版本

```

逐秒数据是唯一主要数值载荷；5 s视图及效应标签按需导出，不长期保留多份重复数组。核心状态180个未来tick，根t状态共享。数值载荷按4.1的uint16/float32/uint8布局估计每分支1,967,040 bytes，196,560条约386.6 GB（约360.1 GiB）；不含新增少量计数、根历史/上下文、索引和文件容器开销，也没有假设压缩收益。Engine Archive仅驻内存，不再写入磁盘预算。

初始按500 GB工作预算安排。本次远端只读检查显示/mnt/pan约1.2 T可用、内存31 GiB、28个逻辑CPU；这些是当前快照，不是预约资源。正式启动前重看可用空间，运行中根据正式已写分片更新完工体积估计，保留至少100 GB磁盘余量；若不够则暂停，不切到系统盘。

每包32条分支，约63 MB原始载荷，压缩后实际体积由正式分片记录。写到临时分片、flush/fsync后原子更名，再提交含hash的完成索引；重启只跳过已完整提交且hash匹配的分片，不把半写文件当成功。原始逐车ID只在运行缓存及根记录器上下文保留，不为每个tick每条分支保存巨大的JSON明细。
