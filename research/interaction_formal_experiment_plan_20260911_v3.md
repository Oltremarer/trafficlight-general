# CityFlow 动作效果与稀疏交互：正式实验设置 v3

日期：2026-09-11。状态：待确认的执行计划，不是已启动或已完成实验。此次仅编写计划；未修改采集器、模型或远程任务。

一句话：先让模型学准“只改一个路口，哪里多等或少等了多少”，再判断加入双路口交互是否能选出更好的联合动作，最后比较少算交互能节省多少计算。

动作链：同一根状态的参考/单项/双项/多项仿真 → 物理单位效果标签 → 单项模型对照 → 冻结单项模型并学习交互 → 相同候选集决策 → 同预算稀疏与完整计时比较。

## 4. 模型输入、标签与指标边界

### 4.1 输入

复用目前已实现的输入，两个单项版本完全相同：

- 车道：三段车辆数/停车数/平均速度/空段掩码、入口尾车距离和速度、历史接纳受限比例、五秒进出事件、车道长度与限速。每车道20维。
- 路口内部：车辆数/停车数、当前相位one-hot、持续时间、过渡标志、静态关联信息。每路口11维。
- 外部入口：待入网车辆、历史生成和准入量、静态信息。每入口5维。
- 关系与动作：8种静态关系；完整8段请求对应的已知过渡与放行掩码；每路口每plan动作编码288维。
- 历史张量 `[30,272,20]`，类型不足20维处填充；有效特征按类型处理，空车道掩码保留。
- 不输入真实未来车辆到达、未来效果、未来参考轨迹、全 flow 的未来摘要、未来拥堵标签。

### 4.2 主要输出

每个单项/双项查询输出 `[272,48]`：240个物理车道 +16个路口内部位置 +16个外部入口，在48个五秒窗中的**有符号停车等待效果**，单位车辆·秒。

每秒对在网车统计 v<0.1 的停车量，对未入网已生成车辆统计外部等待量。每辆车只属于一个位置。沿用当前右端点记录：执行[t,t+1)的信号与仿真后，记录t+1的物理状态；未来第一窗为t+1…t+5的五个读数。每5秒累加，再做同根反事实相减：

`单项 e_i = Y_i − Y_0`

`双项 e_ij = Y_ij − Y_i − Y_j + Y_0`

`联合真值 ΔY_a = Y_a − Y_0`

差值先用 int64 在物理单位计算，再转 float32 和线性归一化。禁止分别 log 每条轨迹后相减。模型输出负数表示相对参考少等待，正数表示多等待。

### 4.3 辅助解释数据，暂不增加预测头

保留逐秒/五秒分段 N/Q、lane/movement 流量、边界生成/准入/积压、速度损失、入口尾车状态、接纳受限时间、完成事件及 unresolved 标记。

这些量用于解释哪里发生了作用，不加入本轮训练多目标权重。速度损失不等于完整旅行延误；接纳受限时间是代理指标，不等于完整 spillback。效应预测也不能直接给出绝对未来风险：在线不使用真实 Y0 来还原未来绝对状态。

## 5. E1：单项模型与训练目标对照

### 5.1 两个版本

- **A_ref**：A2结构和自然逐元素L1/总量/BCE目标，适配新240秒数据。
- **A_MS**：同一A2结构，仅把目标换为多尺度累计效果监督。

两版本均从头训练；同一seed下复用同一初始state_dict与batch顺序。旧 `selected_A.json` 和旧checkpoint只读保留，不作为这次从头训练的初始化。

统一结构：类型投影64维；单层GRU64；两层8关系图传播；动作编码288→64→64；单项有符号值头269→128→64→48；门控头同形状；隐藏激活SiLU，头部Dropout=0.1。单项输出为 sigmoid(gate)×value，并对参考计划严格置零。两个输出末层均零初始化。

### 5.2 损失的具体定义

人话：细粒度项看“每5秒哪里错了”；位置累计项看“同一位置累计多等/少等多少”；全网累计项看“这个动作最终是否更好”。三者均从同一个预测张量计算，不额外训练互相矛盾的reward头。

记 `p` 为反归一化后的预测、`y` 为物理标签，训练累计时域 `H={30,90,180,240}`。

尺度仅由36个训练根确定，单项和双项分别拟合：

- `s5[g]`：各位置类型g内，所有训练五秒效果绝对值的非零P95，最小1车辆·秒。
- `sP[g,h]`：该位置类型、该时域的单位置累计效果绝对值非零P95，最小1。
- `sJ[h]`：全网有符号累计效果先求和再取绝对值，其非零P95，最小1。
- 无非零样本时尺度为1。验证/测试沿用训练尺度，不重新拟合；不按单个样本自适应缩放。

公式中 `mean` 为当前batch查询和标出的全部位置/时域元素的算术平均，不对非零样本过采样；位置仍按自然数量平均，不另改成三类位置等权。

```text
L5 = mean[q,o,k] abs((p-y)/s5[type(o)])
LP = mean[q,o,h∈H] SmoothL1(sum[k<h/5](p-y)/sP[type(o),h], beta=1)
LJ = mean[q,h∈H] SmoothL1(sum[o,k<h/5](p-y)/sJ[h], beta=1)
LJ240 = mean[q] SmoothL1(sum[o,k<48](p-y)/sJ[240], beta=1)
LG = mean BCEWithLogits(gate_logits, y != 0)

A_ref: L = L5 + 0.1*LJ240 + 0.01*LG
A_MS:  L = 0.1*L5 + 1.0*LP + 1.0*LJ + 0.01*LG
```

这些系数是本轮预先固定的设计值，不是已证明最优的比例；不做权重扫描。LJ各时域等权，主决策仍以240秒为准。门控标签仅用于训练，不作为推理掩码。将来若要解释哪个新增损失项单独起作用，需另立消融；本轮只能判断整套累计监督方案的作用。

### 5.3 训练设置

| 参数 | A_ref / A_MS |
|---|---|
| 训练根/单项查询 | 36 / 2,304 |
| 每epoch | 全量单项查询打乱一次；不按非零率挑样本 |
| Batch | 32个单项查询；72个更新/epoch |
| Epoch | 300，无提前停止，共21,600个更新/运行 |
| 种子 | 42、43、44，每版本3次，共6次主训练 |
| 优化器 | AdamW，lr=3e-4，weight_decay=1e-4，betas=(0.9,0.999)，eps=1e-8 |
| 学习率 | 前5epoch线性warmup，之后cosine至3e-5；复用现有learning_rate函数 |
| 梯度裁剪 | L2 norm=1.0 |
| 精度 | FP32；AMP/TF32关闭；现有确定性选项保留 |
| CPU线程/作业 | torch=2，interop=1 |
| 验证 | 每5epoch，完整12个验证根及每根65个候选 |

3+联合真值不得进入梯度或采样权重；训练只用单项标签。验证联合标签可用于checkpoint选择，因此“组合未见”准确指联合标签未用于梯度，而不是从未参与模型选择。

版本选择：分别对每版本三个种子的验证指标取均值，按(regret, joint MAE, 固定版本序)比较；完全同分优先A_ref。选一个统一版本A*，每个seed使用该版本自己选出的checkpoint，禁止逐测试根或逐seed换版本。

## 6. E2/E3：真实分解与交互模型B1

### 6.1 B1训练

- 复制对应seed的A*，整个A网络冻结并保持eval，包括single_gate中的Dropout；仅pair_head训练。
- 编码器每根缓存一次，pair head采用现有410→128→64→48结构，两个节点交换顺序后取平均。只将pair head末层置零，不能重置A。
- 输入是完整的两个路口计划、当前/历史状态、相对位置和信号服务信息；任一计划为参考时交互严格为零。
- 标签是真实 `Yij−Yi−Yj+Y0`，不能用 `Yij−模型单项和` 替代。
- 固定损失为双项尺度下 `0.1*L5 + LP + LJ`；B1没有额外门控头或BCE，不做非零过采样。
- 训练69,120个双项查询，batch=64，1,080更新/epoch，100epoch，共108,000更新/seed，三个seed。优化器、精度、学习率日程、裁剪与A相同，日程最大epoch换为100。
- 验证每5epoch；额外把epoch 0作为合法checkpoint。选择规则仍为验证regret→joint MAE→较早epoch。若epoch 0胜出，明确报告“加入学习交互未改善所选checkpoint”，不能包装成正结果。
- 不训练B2，也不让交互梯度反传更新A。

### 6.2 分解参照

在完整65候选集及3/4/8/16规模切片分别计算以下方法，全部使用同一根、相同候选和相同等待目标：

| 名称 | 组成 | 用途 |
|---|---|---|
| Zero/Reference | 所有效果0，平局选参考 | MAE零值参照、参考动作决策 |
| True-S | 真实单项和 | 忽略交互本身的误差与regret |
| True-SP | 真实单项+真实双项和 | 高阶残差和二阶可组合性 |
| Pred-S | A*预测单项和 | 可部署单项基线 |
| Pred-S + True-P | 预测单项+真实双项 | 诊断单项误差，不是可部署方法 |
| True-S + Pred-P | 真实单项+B1交互 | 诊断交互误差，不是可部署方法 |
| Pred-SP | A*+B1 | 可部署完整组合模型 |

对3+动作，真实双项不能从该联合结果反推，必须从另外采集的真实双项分支得到。两路口重构恒等式不作为高阶验证。

高阶残差 `R=ΔY_joint−Σe_i−Σe_ij` 同时报：细粒度MAE、位置累计MAE、全网有符号累计误差、绝对残差和/真实效果绝对值和。分母为0时报告NA与绝对误差，不用任意epsilon制造比例。

## 7. E4：稀疏筛选的可执行设置

### 7.1 为什么需要一个轻量筛选头

“只算8对”必须在详细预测之前决定是哪8对，不能用全部1920个详细预测或测试真实交互来挑选。本轮增加一个小排序头R，使用冻结的A*编码器；它是额外可训练头，成本单列，不计成免费步骤。

对每个根的每个无序路口对，训练标签为：

`z_ij = max[两个非参考计划的16种组合] abs(sum[所有位置和48窗] e_ij)`。

它表示该对路口可能改变全网等待的最大幅度，不是spillback概率。只关心全网等待而在空间上互相抵消的交互可能得低分，这是本轮目标下的有意取舍。

固定实现：

- 对称输入197维：`h_i+h_j`、`h_i*h_j`、全网平均embedding，各64维；加`|dx|/1000、|dy|/1000、距离/1000、hop/8、是否相邻`五维。
- MLP 197→64→1，SiLU，末尾Softplus，无Dropout，共12,737个参数。输出预测的非负log强度。
- 标签变换 `log1p(z/c)`，c为训练路口对非零z的P95、最小1。这个变换只用于筛选强度，不用于可加效果标签。
- 每seed 36×120=4,320条训练样本，batch64，100epoch，68更新/epoch；不足一批不丢弃。验证12×120=1,440条。
- 使用独立AdamW和梯度裁剪，参数/日程同B1；输入detach，R梯度不改变A或B1。可放在对应B1作业内执行，但其6,800个更新必须独立记录。
- R按验证log强度SmoothL1最小→较早epoch选checkpoint；不根据测试集或某个K的测试regret选择R。

### 7.2 比较组与实际计算量

| 方法 | 如何选对 | 详细双项查询/根 | 单项查询/根 |
|---|---|---:|---:|
| Pred-S | 不计算交互 | 0 | 64 |
| All-120 | 全部120对 | 1,920 | 64 |
| Adj-24 | 物理相邻的24对 | 384 | 64 |
| Top-32 | R预测分数最高32对 | 512 | 64 |
| Top-24 | R预测分数最高24对 | 384 | 64 |
| Top-8 | R预测分数最高8对 | 128 | 64 |

Top-24用于与Adj-24做同预算比较；它只是已有模型的额外评估档位，不新采标签或另训模型。R每根一次性给120对标量打分，平分按固定(i,j)顺序。一个根选出的对供65个候选共同使用。

只对选中的K对详细预测各16种动作组合，未选交互置零。详细因子推理batch上限128；利用FP64因子总量完成候选计分，必要时仅重构所选动作的完整效果场，避免为计分物化全部65个场。

报告Top-K保留的真实z强度比例及未保留强度，只作离线诊断，禁止用真实z在线选择。图上“有非零交互的路口对比例”和“全部位置/时间元素的非零率”分别报告。

## 8. 评价指标、选型与数据使用顺序

### 8.1 统一决策目标

`J(a)=未来240秒的在网停车等待 + 已生成未入网等待`。

模型只比较预测的ΔJ，共同参考未来Y0不作为推理输入。动作平局统一为FP64分数距最小值不超过1e-6车辆·秒，选冻结候选列表最前者；参考放第一个。实际最优也用同一报告容差。

主要指标：

1. `regret=J(模型选择)−min[65候选]J`，单位车辆·秒，越低越好。
2. 最优候选命中率，以及选择后比参考更差的比例与超额等待。
3. 相对参考的收益及最优可获得收益；收益捕获率`(J0−J选择)/(J0−J最优)`。分母为0时NA，不截断负值。
4. 联合/单项/双项的全网累计效果MAE、bias；位置累计MAE；逐五秒MAE与全零参照；零/非零位置MAE、非零符号准确率。

固定评价时域30/60/90/120/180/240秒。240秒是主决策时域；其他时域重新比较同一动作列表并单独报告，不依据测试结果反选训练时长。

固定切片：来源cohort、需求profile、策略、根时刻、3/4/8/16个干预路口、连通/均匀联合动作、路口对距离。不给只在成功案例上计算的“总体提升”。

### 8.2 汇总与测试使用

- 每seed先在同一需求条件内平均两种策略，再在cohort内平均条件，最后对三个cohort等权平均。主结果报告三个seed均值和训练seed标准差，并展示每个cohort结果。
- 同表给逐根配对差值和最坏根。不能把分支/位置/时间窗当独立样本计算显著性；测试仅三个cohort，不以窄置信区间包装泛化确定性。
- 验证集允许选择A版本、A/B/R checkpoint；测试标签不进入训练、尺度估计、筛选目标拟合或阈值设定。
- 主模型与checkpoint全部锁定后才生成/读取测试模型评价。采集期间只查看测试数据进度、文件数和错误，不用其效果强度或排序结果选型。
- True-S/True-SP参照不参与模型选型；测试结果出来后如需改方法，改动视为下一轮，不反复把这12根称为盲测。
- 不设置“指标达到某个数才允许继续”的新增门槛。按依赖完成已批准实验；结果不理想也如实完成对照，不自动加参数搜索。

## 9. 计算代价与公平计时

### 9.1 训练与采集预算

- 主采集：122,940分支×240秒 =29,505,600仿真秒；另计来源轨迹重放和物理记录开销。
- A主训练6次；B1主训练3次；R轻量训练3次，随对应B1作业排程但单独记时和记更新。总共9个主要训练作业，包含12个训练组件，不称只有9个学习器。
- 标签量：训练单项2,304，训练双项69,120，训练R样本4,320；3+标签不进梯度。
- 双项float32训练标签约3.61GB，全60根约6.02GB（十进制，仅效果张量）；使用分根文件或memmap按batch读取，不在每个GPU作业里重复常驻全量原始分支。

### 9.2 在线计时定义

所有checkpoint锁定后，停止本任务采集/训练占用，使用12个测试根独立计时。若同机有其他用户任务，不擅自停止，记录干扰并推迟隔离计时。

- 模型端每seed/根/方法：10次预热、50次计时，batch=1个根；包含历史聚合/归一化、已知动作编码、CPU→GPU传输、一次状态编码、R筛选（如有）、实际因子推理、组合计分、argmin和所选动作/效果的必要读回。CUDA计时前后同步。
- 方法固定为Pred-S、All-120、Adj-24、Top-32、Top-24、Top-8。报告每根median/p95，再给组汇总；不把不同seed当新的环境。
- 两种方法的输入起点均为已在内存中的根状态/历史和同一候选列表。磁盘加载、起点到根的重放和checkpoint加载单独报告，不混入一次在线决策延迟。
- CityFlow直接lookahead：同一CPU、每Engine1线程、单根65候选顺序恢复并rollout；只读取计算相同J需要的逐秒停车数和未入网等待，不写训练用全量字段。包含恢复、信号执行、J计算与选择。
- CityFlow计时每测试根完整跑3遍，不做模型seed的重复：12×65×3=**2,340次计时分支**，明确额外列入预算，不增加训练样本。启动/首次初始化另记，不伪装已预热。
- 总仿真分支预算因此为122,940采集 +2,340计时 =**125,280次**。计时分支不改变主候选或参数，不是先导试验。
- GPU模型与CPU CityFlow的硬件差异、线程数、精度、软件版本必须同表列出。采集阶段的丰富记录时间只称采集时间，不能直接当作公平的simulator planning耗时。
- Model speedup使用匹配根的CityFlow决策时间/模型端到端决策时间；同时报告训练/数据采集成本，不声称这些离线成本不存在。
